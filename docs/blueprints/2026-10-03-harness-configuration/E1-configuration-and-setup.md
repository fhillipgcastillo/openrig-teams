# Spec: E1 `configuration and setup`

## Goal anchor
Keep one reusable set of OpenRig team templates supporting Claude Code, Codex, and mixed teams, with explicit machine-local runtime and approval preferences and project-specific onboarding kept outside shared defaults.

- AC1 Setup prompts for the initial runtime and approval choices, accepts equivalent flags, persists them locally, and reuses them without rewriting tracked templates.
- AC3 Codex auto-review is optional. Claude native/auto selection uses supported OpenRig operations and accurately reports the first-launch limitation; no implicit restarts or bypass.
- AC5 Tests use temporary configurations and mocked lifecycle commands; the user's staged README edit, running rigs, project profiles, and approval-design-session.md are preserved.

## Contract
- Interface: C2 and C3.
- C1 Configuration: `${OPENRIG_TEAMS_CONFIG:-${XDG_CONFIG_HOME:-$HOME/.config}/openrig-teams}/runtime.json`, JSON object `{ "version": 1, "runtime": "codex" | "claude-code", "approvals": { "codex": "native" | "auto", "claude-code": "native" | "auto" }, "seats": { "<team>.<member>": { "runtime"?: "codex" | "claude-code", "approval"?: "native" | "auto" } } }`. Valid seats: `lead.lead`, `pm.pm`, `fe.builder`, `fe.reviewer`, `fe.tester`, `be.builder`, `be.reviewer`, `be.tester`, `devops.operator`. Missing/invalid configuration fails actionable at plan/up; lifecycle down/remove/name remains available. Native means ordinary OpenRig launch behavior plus native user/managed rules; applying Claude native records `floor`, not `inherit`, and does not clear native permission rules.
- C2 Library `lib/runtime-config.mjs` exports `configDir(env = process.env): string`, `loadSettings(env = process.env): C1`, `resolveSeat(settings, team, member): { runtime, approval }`, `findOpenRigPackage(env = process.env): string`, and `validateSettings(settings): C1`. Unknown fields/seat names and invalid values fail. OpenRig package discovery follows `rig` on PATH to its real path and locates `daemon/specs/agents/shared` without daemon access.
- C3 Setup CLI: `bin/setup [--runtime codex|claude-code] [--codex-approvals native|auto] [--claude-approvals native|auto] [--seat <team>.<member>=codex|claude-code] [--seat-approval <team>.<member>=native|auto] [--plan]`. First setup asks on a TTY for omitted relevant choices; noninteractive initial setup requires runtime and approval choices for every selected runtime. Unselected harnesses initially store `native`; an existing stored choice is retained when later selecting that harness. Existing settings are retained except explicit overrides. Exit 0 success, 1 invalid input/config/dependencies. Plan writes nothing. Only selected Codex auto installs the existing `openrig-auto.config.toml`, preserving identical files and refusing differing files. Setup checks selected CLIs are available and reports their auth checks to the user; it never installs a CLI, logs in, launches rigs, or edits global permission allowlists. Existing `config.env` and project profiles are preserved.

## Context
- `bin/setup:9` requires `rig` on PATH; `bin/setup:11` discovers its package through the executable's real path, currently with an npm fallback. Replace discovery with C2's shared helper.
- `bin/setup:24` installs the Codex profile unconditionally before checking package discovery, the ordering this element must correct.
- `bin/setup:36` creates the shared-agent symlink and each rig's culture link; `bin/setup:40` creates home directories. Preserve these setup outcomes.
- `bin/setup:42` uses the same configuration directory expression as `bin/rig-job:8`; `bin/setup:44` creates the default spawn-authorization file only if absent. Preserve its content and ownership semantics.
- `profiles/openrig-auto.config.toml:1` supplies workspace-write, on-request, and auto_review settings. Install its exact bytes only when an effective seat selects Codex auto.
- `.gitignore:1` through `.gitignore:4` already ignore generated setup links, homes, and generated rig specs.
- `bin/rig-job:19` sources `config.env`; `bin/rig-job:51` uses `projects/<project>.sh`. Runtime JSON must remain separate from both.
- `lessons-learned.md:9` requires reusable role definitions and machine preferences to remain separate.

## Behavior
1. `configDir(env)` implements the exact nonempty-value fallback in C1. Empty environment variables behave like Bash's `:-`. Resolve the selected path consistently; missing HOME when needed must produce an actionable error, not a path containing `undefined`.
2. `validateSettings(settings)` accepts only a non-null object with exactly `version`, `runtime`, `approvals`, and `seats`. Require version numeric 1, one supported runtime, both approval keys with supported values, and an object of the nine supported seats. Reject arrays, nulls, unknown fields at every level, unsupported seats, invalid versions, and malformed seat objects. Seat override objects may contain either/both runtime and approval or be empty. Return the validated settings without changing their values.
3. `loadSettings(env)` reads runtime.json, parses JSON, and validates it. Missing, malformed, or invalid configuration throws an Error naming the path and explaining to run/configure `bin/setup`. Do not create files or silently repair invalid settings.
4. `resolveSeat(settings, team, member)` rejects unknown seats. Effective runtime is the seat runtime override or global runtime. Effective approval is the seat approval override or the approval for the effective runtime. An approval-only override therefore follows a later global runtime switch. Do not mutate settings.
5. `findOpenRigPackage(env)` finds executable `rig` using the supplied PATH, follows its symlink to its real path, and walks parent directories until `daemon/specs/agents/shared` exists as a directory. Return that package directory. Do not invoke a daemon, `rig setup`, or npm installation; fail clearly when the executable or resource tree is absent.
6. Setup parses the exact C3 flags, supports repeated seat flags for distinct seats, and rejects unknown flags, missing arguments, invalid values, malformed assignments, or duplicate conflicting assignments before mutation. A help option may print usage without prerequisites or mutations. Explicit overrides merge onto validated existing settings and retain all unrelated values and seats.
7. On first setup, gather global runtime and per-seat runtime overrides before determining effective harnesses across all nine seats. On TTY, prompt for each omitted relevant approval choice using explicit native/auto wording. On non-TTY, require the runtime and approval choice for each selected harness; supply each selected harness's global approval preference through its approval flag, then apply any seat-level approval overrides. Do not hang waiting for piped stdin. Persist the complete C1 shape with an empty seats object if no overrides exist.
8. Initially unselected harnesses store native approval unless explicitly configured through their approval flag. When settings already exist, retain stored choices rather than prompting anew. A later switch to another runtime uses its stored approval preference unless explicitly overridden.
9. Derive required CLIs and optional profile installation from the nine effective seat resolutions, not just the global runtime. Verify selected `codex` and/or `claude` executables exist on PATH. Report the user's authentication checks (`codex login status` and `claude auth status`) without logging in or claiming successful authentication. Missing runtime CLIs fail before mutations, with the missing executable and selected runtime identified.
10. If any effective Codex seat uses auto, require the checked-in profile source and inspect the destination `${CODEX_HOME:-$HOME/.codex}/openrig-auto.config.toml`. An identical regular file is preserved byte-for-byte; a differing/unreadable destination fails before any setup mutation. Do not touch an existing profile at all when no selected seat requires it. Native selection never removes an earlier profile.
11. Preflight all argument, configuration, package, CLI, selected-profile, and setup-link conflicts before creating directories or writing files. Protect ordinary directories/files occupying setup symlink destinations; existing expected symlinks may be refreshed. Preserve `config.env`, existing project profiles, tracked templates, and instruction files.
12. `--plan` performs the same validation and displays resolved runtime/approval choices plus planned links/directories/profile actions. It writes no files, no temporary config, and no links; do not call rig lifecycle commands. Missing dependencies or conflicts fail equally in plan mode.
13. Apply the existing setup links/directories and create default config.env only when absent. Write runtime.json with a unique adjacent temporary file and atomic rename; avoid rewriting an unchanged runtime.json. Clean up a temporary file when its write/rename fails. Persistence should occur only after all preflight succeeds. Entire setup need not roll back an unexpected I/O failure; report the error honestly rather than success.
14. Setup exits 0 on success and 1 on invalid input/config/dependencies or filesystem failures. Report config location, effective choices, changed/preserved optional profile, and auth-check instructions. Mention Claude auto's first-registration limitation without performing seat permission changes: E2 owns them. Never launch/resume/restart rigs, change permission allowlists, authenticate, install CLIs, or alter spawn authorization.

## Implementation
1. Add dependency-free `lib/runtime-config.mjs` using Node built-ins and the five named exports from C2. Shared constants/helpers may be private; E2 must need only the public exports. Keep library import free of setup side effects.
2. Convert `bin/setup` to a Node executable or a small shell launcher backed by the module; preserve its executable entry point and repository-root discovery independent of current working directory. If using a shell launcher, add a dedicated setup implementation module instead of embedding JavaScript in shell quoting.
3. Organize setup as parse, load/merge/prompt, validate effective selections, preflight dependencies/conflicts, display plan or apply, report. Keep file mutations out of validation functions.
4. Resolve commands with argument-safe filesystem/process APIs; do not interpolate user values into shell commands. Existing `rig --version` output may be retained with a direct argument-array invocation, but tests must provide a fake executable.
5. Add `tests/runtime-config.test.mjs` using `node:test`, `node:assert/strict`, and temporary filesystem fixtures. Unit-test library exports directly and execute setup in copied temporary repository fixtures for integration tests. Copy only required setup/lib/profile/rig structure; never execute setup against the working repository or real configuration homes.
6. Inject PATH, HOME, CODEX_HOME, OPENRIG_TEAMS_CONFIG, and XDG_CONFIG_HOME explicitly in every integration fixture. Provide fake rig/codex/claude executables and a fake OpenRig resource directory reached through a rig symlink. Collect all fake rig calls and reject lifecycle/auth/install commands. Use Node's executable path explicitly where a restricted fake PATH would hide Node.
7. Keep explanatory prose outside function bodies. Contract comments, if any, must be one line describing accepted inputs/returned outputs. Do not edit README, templates, profiles, or approval-design-session.md in E1.

## Tests
- Directory precedence: explicit OPENRIG_TEAMS_CONFIG wins over XDG_CONFIG_HOME/HOME; empty values fall through to the next choice.
- Settings validation: valid all-default and mixed objects return valid values; null, arrays, missing keys, unknown top-level/nested keys, unknown seat, version 2/string 1, runtime `claude`, and approval `bypass` each throw actionable errors.
- Seat resolution: global codex/native plus `fe.reviewer` runtime claude-code and global Claude auto resolves reviewer to claude-code/auto and builder to codex/native; an explicit reviewer native overrides global Claude auto.
- Missing config and malformed JSON: load throws with runtime.json path and setup guidance, without writes.
- Package discovery: executable symlink under fake PATH resolves the fake package through parent walking; missing rig/resource tree fails without invoking rig.
- Initial noninteractive Codex/native: `--runtime codex --codex-approvals native` exits 0, creates valid runtime.json/setup links/default config.env/projects, requires no Claude executable, and does not create a Codex profile.
- Initial Claude/native: `--runtime claude-code --claude-approvals native` exits 0 with no Codex executable or profile required.
- Missing choices: no runtime or no relevant approval selection exits 1, creates no configuration or setup links, and never reads interactive input when stdin is not a TTY.
- Mixed setup: `--runtime codex --codex-approvals native --seat fe.reviewer=claude-code --claude-approvals auto` persists the reviewer override and both approvals, requires both CLIs, and executes no permission mutation.
- Seat approval-only auto: `--runtime codex --codex-approvals native --seat-approval fe.reviewer=auto` creates the exact profile bytes because that effective seat requires it.
- Optional-profile preservation: selected auto with identical existing profile succeeds preserving the file; differing profile fails before any mutations; a differing profile is ignored successfully when effective seats all use native or Claude.
- Rerun: no flags with valid existing settings reuses values without prompts; overriding one seat retains other seats, approvals, custom config.env bytes, and project-profile bytes. An unchanged runtime file retains bytes and mtime.
- Plan: valid first configuration with `--plan` prints choices/actions and exits 0 while the fixture tree remains unchanged; invalid input/dependency/profile conflict exits 1 and also leaves it unchanged.
- Failure isolation: nonexistent selected CLI, unavailable OpenRig resources, malformed existing config, ordinary file/directory at a symlink target, unknown flag, and malformed override each exit 1 before mutations.
- Atomic persistence: the final runtime.json parses and contains the complete chosen settings; no abandoned temporary file remains on success. Exercise failed writes in an isolated fixture where permissions or an invalid parent shape cause a real I/O error without touching the user's environment.
- Interactive entry point: exercise first-run prompts through an available pseudo-terminal with omitted runtime/approval answers, confirm chosen values and clean cancellation; if the environment lacks a PTY runner, state that narrow verification limit explicitly and test the prompt/selection routine separately with deterministic input/output adapters.
- Scope: fake-command logs contain no `up`, `down`, `seat set-permissions`, `setup`, login, or CLI installation; all writes remain within temporary fixture roots.
