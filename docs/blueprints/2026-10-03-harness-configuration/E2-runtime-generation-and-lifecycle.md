# Spec: E2 `runtime generation and lifecycle`

## Goal anchor
Keep one reusable set of OpenRig team templates supporting Claude Code, Codex, and mixed teams, with explicit machine-local runtime and approval preferences and project-specific onboarding kept outside shared defaults.

- AC2 Lead, PM, and department launches resolve the same configuration, including per-seat overrides; both harnesses retain their runtime resources.
- AC3 Codex auto-review is optional. Claude native/auto selection uses supported OpenRig operations and accurately reports the first-launch limitation; no implicit restarts or bypass.
- AC4 Documentation and instruction loading support both harnesses; exclusions protect the files the selected runtimes actually write.
- AC5 Tests use temporary configurations and mocked lifecycle commands; the user's staged README edit, running rigs, project profiles, and approval-design-session.md are preserved.

## Contract
Interface: C4, C5, C6.

- C1 Configuration: `${OPENRIG_TEAMS_CONFIG:-${XDG_CONFIG_HOME:-$HOME/.config}/openrig-teams}/runtime.json`, JSON object `{ "version": 1, "runtime": "codex" | "claude-code", "approvals": { "codex": "native" | "auto", "claude-code": "native" | "auto" }, "seats": { "<team>.<member>": { "runtime"?: "codex" | "claude-code", "approval"?: "native" | "auto" } } }`. Valid seats: `lead.lead`, `pm.pm`, `fe.builder`, `fe.reviewer`, `fe.tester`, `be.builder`, `be.reviewer`, `be.tester`, `devops.operator`. Missing/invalid configuration fails actionable at plan/up; lifecycle down/remove/name remains available. Native means ordinary OpenRig launch behavior plus native user/managed rules; applying Claude native records `floor`, not `inherit`, and does not clear native permission rules.
- C2 Library `lib/runtime-config.mjs` exports `configDir(env = process.env): string`, `loadSettings(env = process.env): C1`, `resolveSeat(settings, team, member): { runtime, approval }`, `findOpenRigPackage(env = process.env): string`, and `validateSettings(settings): C1`. Unknown fields/seat names and invalid values fail. OpenRig package discovery follows `rig` on PATH to its real path and locates `daemon/specs/agents/shared` without daemon access.
- C4 Runtime helper CLI: `bin/rig-runtime render <team> <rig-name> <output-path>` writes a generated spec using C1/C2 and OpenRig's installed YAML parser; `bin/rig-runtime permissions <team> <rig-name> [--plan]` shows/applies native permission selections for Claude seats only, verifies actual seat runtime before mutation, and refuses mismatches. `bin/rig-runtime check <team>...` validates settings and selected CLI/profile prerequisites before job mutations and prints exactly `codex`, `claude-code`, or `both` on stdout; diagnostics go to stderr. Codex auto requires an identical installed profile and successful `codex -p openrig-auto mcp list` loader probe (captured output, 10-second timeout). Permission application queries `rig ps --nodes --rig <rig-name> --json`, verifies every expected seat runtime before any mutation, and then sets Claude modes. Exit 0 success, 1 failure. Claude auto maps to `rig seat set-permissions <pod>-<member>@<rig-name> --mode auto --reason <reason>`; native maps to `floor`. Codex auto adds `codex_config_profile: openrig-auto`; native omits it. No bypass modes or broad command allowances are added.
- C5 Wrapper actions: existing `plan|up|down|resume|remove|name` retain meaning; `permissions` explicitly applies saved Claude preferences. Plan generates a separate ignored `.plan.yaml` and prints deferred permission steps without executing them. Up renders, launches, then saves Claude choices with a clear next-launch notice. Resume applies configured Claude choices to verified existing seats before `rig up <name> --existing`; it never changes the stored harness of a seat. Harness and Codex named-profile changes affect newly generated rigs; changing an existing rig's harness requires deliberate recreation outside this feature. Claude approval changes are the explicit supported exception: permissions/resume applies the saved choice to verified same-runtime seats for their next launch. `rig-job` validates selected teams before branch/worktree changes and passes selected runtime information to exclusions.
- C6 Exclusions: `bin/rig-exclude <project> [--runtime codex|claude-code|both]`; default `both` preserves existing calls. Runtime-specific collision checks cover only selected runtimes; exclusion blocks retain previously installed artifact patterns so simultaneous jobs using other runtimes stay hidden. Keep current refusal of tracked generated files. Job launch computes the union of effective runtimes across its selected teams and supplies it. Project instruction bridging remains the project profile's responsibility; never overwrite or copy instruction files generically.

## Behavior
1. Validate helper command arity, team names, rig names, and settings before writes or lifecycle calls. Resolve members from the relevant existing template and C2; reject unknown members rather than silently leaving an unconfigured runtime. Diagnostics identify the team/seat and corrective setup command.
2. Render a clone of parsed YAML, replacing the name and each member runtime. First delete every `codex_config_profile`; add `openrig-auto` only for effective Codex auto seats. Preserve every other template field and validate with installed RigSpecSchema before writing. Never create a Claude permission YAML key. Never mutate tracked templates. Use temp-file plus rename for generated specs.
3. `check` verifies every requested team's effective runtime executable (`codex` or `claude`) is executable on PATH, validates the OpenRig package/parser/schema prerequisites, and requires the selected Codex auto profile at `${CODEX_HOME:-$HOME/.codex}/openrig-auto.config.toml` to match the shipped profile. Probe `codex -p openrig-auto mcp list` with a bounded timeout and propagate failure before any job mutations. Do not install missing dependencies, authenticate, change permissions, or launch a rig. Claude eligibility remains the daemon's authoritative check during selection; do not infer support from unrelated local help output.
4. Permissions plan reads only configuration/template data and prints the canonical seat, intended mode, and explicit future-launch limitation. It must work before a rig exists and must not query/mutate live permission state. Real permissions first query `rig ps --nodes --rig NAME --json`, verify every expected canonical seat occurs exactly once under the specified rig and matches its configured runtime, and only then begin mutations. Missing, duplicate, malformed, unknown-runtime or mismatched seats fail before any permission write. Verify Codex seats too so resume cannot conceal a runtime mismatch in an all-Codex rig.
5. For each verified Claude seat, invoke `rig seat set-permissions POD-MEMBER@NAME --mode auto|floor --reason REASON`, with a stable human-readable reason identifying openrig-teams and the saved selection. Codex receives no permission mutation. Stop on the first failure, propagate it as helper exit 1, and retain the useful daemon error. A batch can partially succeed if the daemon refuses a later seat: state that preceding selections may already be saved; never roll back by choosing weaker permissions or restart any process.
6. `rig-home` gains `permissions` and `name`, validates action before side effects, and preserves names lead/pm. Generate `rigs/TEAM/rig.generated.yaml` for up and `rigs/TEAM/rig.generated.plan.yaml` for plan. Make home directories only for plan/up where required. Down/remove/name avoid runtime loading and preserve existing lifecycle commands.
7. `rig-team` retains linked-worktree validation and rig naming. Up keeps `rig.PROJECT-JOB.yaml`; plan uses `rig.PROJECT-JOB.plan.yaml`. Remove cleans corresponding generated artifacts only after successful existing removal. Name/down/remove work without runtime.json or harness CLIs.
8. Plan checks prerequisites, renders only its separate plan file, calls existing `rig up SPEC --cwd CWD --plan`, then displays deferred Claude selection commands. Up checks prerequisites, renders launch spec, invokes existing `rig up SPEC --cwd CWD --yes`, and only after success applies permissions. Print that Claude preferences affect a later launch; first launch uses ordinary OpenRig behavior. Failed up never applies permissions. Failed post-up selection is an error even though the rig may already exist; report this without an automatic stop/relaunch.
9. Resume checks prerequisites, verifies runtime identities and applies permissions before calling `rig up NAME --existing`. Do not render over an existing rig or pretend a Codex profile change affects its stored spec. A harness mismatch explicitly explains deliberate recreation is needed and aborts. Permissions action saves the choices only; never invokes up/down/resume.
10. Job start parses the full selected department-team list and preflights all teams together after loading profile/default teams and before branch creation, worktree hooks, copies, exclusions or rig calls. Empty/unknown/home teams fail. Use the union of selected teams' effective runtimes for exclusions: codex, claude-code, or both. Preserve existing caller authorization, profile functions, copying and brief behavior. Plan performs read-only preflight while retaining its existing would-run behavior. Finish remains independent of runtime settings.
11. Exclusions accept an optional trailing `--runtime` argument with exact C6 values; absent means both. Shared entries: `.openrig/`. Claude entries: `CLAUDE.local.md`, `.mcp.json`, `.claude/settings.local.json`, `.claude/plugins/shared:openrig-core/`, and role `.claude/skills/` directories. Codex entries: `AGENTS.md`, `.codex/plugins/shared:openrig-core/`, and role `.agents/skills/` directories. Keep the existing skill discovery and marked-block convention. Check collisions for precisely the selected block before writing and preserve exit 2. Merge previous artifact patterns into the block without rechecking unrelated runtime collisions. Never write or copy project instructions.
12. Tests must never address running user rigs. Copy the necessary wrapper/template/library files into a temporary fixture, use temporary configuration and HOME/CODEX_HOME, and put mocked rig/codex/claude executables first on PATH. Capture argv as JSON; fail any unexpected lifecycle call. For schema integration tests, use the installed package only for direct module parsing/validation, not daemon commands.

## Implementation
1. Consume E1 exports and E3 final templates without duplicating their configuration schema. Use an executable Node entry point for `bin/rig-runtime`; resolve installed yaml with `createRequire` anchored inside discovered OpenRig. Import its schema by file URL.
2. Implement small helpers for team/template resolution, prerequisite validation, rendering, canonical seat inventory, and permission command generation. Keep command execution as argv arrays, never interpolate user input into shell source. Return concise errors and helper exit 1.
3. On success, check prints exactly the effective runtime union (`codex`, `claude-code`, or `both`) to stdout; diagnostics go to stderr. Job captures that result without duplicating the resolver. The loader probe output is captured with a 10-second timeout.
4. Wire wrappers to the helper in the ordering above and preserve existing non-launch commands. Explicitly check failure statuses; do not let `rig-job finish`'s existing tolerant handling spread to start/preflight.
5. Add runtime-aware exclusion selection and job union handoff. Update usage strings and `.gitignore` only if necessary for chosen generated names.
6. Add Node built-in tests in `tests/runtime-launch.test.mjs`; reuse E1 fixture patterns where available. Ensure fixtures cannot resolve the real rig executable for lifecycle commands.

## Tests
- Missing runtime.json: home/team plan/up and job start exit 1 with setup guidance; mock log contains no up/permission call and temporary project has no new branch/worktree.
- Mixed FE: default Codex native, reviewer Claude auto, tester Codex auto → rendered runtimes exactly `[codex, claude-code, codex]`; only tester gets profile `openrig-auto`; schema validation passes and tracked template bytes are identical.
- Claude native FE → all Claude runtime, zero Codex profiles, planned floor selections for all three canonical seats.
- Plan preservation: seed launch file with a sentinel, run plan → sentinel unchanged, separate ignored plan file produced, only mock `rig up ... --plan` called, zero set-permissions calls.
- Up sequencing → check/probe before up, inventory after successful up, Claude selections after complete inventory verification. Notice contains future-launch limitation. Mock failed up → zero inventory/permission calls.
- Resume sequencing → complete inventory verification and Claude selections precede `up NAME --existing`; failed selection → no up.
- Wrong stored runtime on the last seat → exit 1, no set-permissions calls even for earlier valid Claude seats, no resume.
- Missing/duplicate expected seat, null runtime, malformed JSON, wrong rig → exit 1 before any mutation.
- All-Codex permission action verifies expected runtimes then does zero set-permissions calls.
- Claude daemon refusal of auto → error retained, no fallback to floor/full_bypass, no implicit restart.
- Missing/mismatched/unloadable Codex profile and missing selected CLI → job start fails before branches, worktrees or profile hooks run. Unselected runtime CLI/profile missing → accepted.
- Lifecycle escape: without config or harness CLIs, team name/down/remove and home name/down/remove retain the original rig name/argv and avoid runtime helper dependencies.
- Tracked AGENTS.md with Claude-only exclusions → succeeds; with Codex/both → exit 2 and exclude bytes untouched. Tracked CLAUDE.local.md mirrors this for Claude/both. Both always refuses either collision.
- Exclusion rerun → one marked block, outside content preserved, runtime-specific artifact paths selected exactly.
- Job selected FE+BE with a Claude seat in BE → excludes `--runtime both`; Codex-only → codex; Claude-only → claude-code. Unknown or empty team list → zero branch/worktree/lifecycle mutation.
- Generated files match `git check-ignore` patterns; role resources and culture references resolve from generated spec directories.
